# 공유 스타일 스펙 (PDF/HWPX/XLSX 렌더링 일관성) — 설계

## 배경

Safety-RAG는 같은 문서 기록(`record["draft"]`, 마크다운 텍스트)을 세 개의 독립된 렌더러(`export_xlsx.py`, `export_hwpx.py`, `export_pdf.py`)가 각자 `parse_markdown_tables()`로 파싱해 XLSX/HWPX/PDF로 변환한다. 데이터 내용은 세 포맷이 동일하지만, **셀 스타일링(열너비 비율, 헤더 배경색, 위험등급 A/B/C 조건부 배경색, 헤더별 정렬, AI 제안값 표기 방식)이 렌더러마다 따로 구현되어 있어** 같은 문서인데도 포맷별로 보이는 모습이 다르다:

- **XLSX**(`export_xlsx.py`): 문서유형별 열너비, 헤더 배경색(`2F5496`/`E3ECEF`), 위험등급 A/B/C 조건부서식(`F8CBAD`/`FFE699`/`C6E0B4`), 헤더별 가운데/왼쪽 정렬, AI 제안값(`"A(AI 제안값, 현장 확인 필수)"`)을 순수값+셀 코멘트로 분리 — 전부 구현됨
- **PDF**(`export_pdf.py`): 열너비 균등분할뿐, 배경색·조건부서식·헤더별 정렬 없음, AI 제안값 문구가 셀에 그대로 노출됨
- **HWPX**(`export_hwpx.py`): 열은 페이지 폭에 맞추지만 균등분할, 배경색·조건부서식·헤더별 정렬 없음(코드 주석상 "베타0 HWPX 수요 신호 없어 의도적으로 단순화"), AI 제안값 문구도 셀에 그대로 노출됨

이번 작업은 **생성 파이프라인(LLM 프롬프트, 마크다운 출력, 저장 포맷)은 건드리지 않고**, 이미 파싱된 표를 "어떻게 그릴지"만 문서유형별로 한 곳에서 정의해 세 렌더러가 공유하도록 만든다. 원래 검토됐던 "B안"(LLM 출력 자체를 구조화 JSON으로 바꾸는 전면 리팩터링)과는 범위가 다르다 — 그건 데이터 모델 완전성(작업계획서 필드 다형성 등) 문제이고, 이번 작업은 순수 렌더링 일관성 문제다.

## 목표

- 같은 레코드를 XLSX/HWPX/PDF로 각각 내려받았을 때 열너비 비율, 헤더 배경색, 위험등급 A/B/C 배경색, 헤더별 정렬이 세 포맷에서 동일하게 보인다.
- AI 제안값(빈도/강도/위험등급/개선후 위험등급)은 세 포맷 모두 셀에는 순수값만 표시하고, 안내문구("AI 제안값, 현장 확인 필수")는 표 아래 각주로 1회만 표기한다.
- 오늘 세션에서 QA 완료한 생성 결과·XLSX 셀 값(숫자/문자 타입, 조건부서식 범위)은 회귀 없이 그대로 유지된다.

## 비목표

- LLM 프롬프트, 마크다운 생성 로직, 레코드 저장 포맷 변경 — 안 함
- 위험성평가표 외 문서유형(작업계획서 작업유형별 확장 필드 등)의 데이터 모델 재설계 — 안 함
- 원래 "B안"(구조화 JSON 스키마 전면 전환) — 별도 사안으로 보류, 이번 스펙 범위 밖

## 렌더러별 변경

### XLSX (`export_xlsx.py`)
- `_COLUMN_WIDTHS_BY_DOCUMENT_TYPE`, `_CENTER_ALIGN_HEADERS`, `_RISK_GRADE_HEADERS`, `_RISK_*_FILL`, `_parse_ai_score_cell`를 전부 제거하고 `document_styles`에서 import.
- 동작은 오늘 QA한 것과 100% 동일해야 한다 (색상 hex 값, 열너비 숫자, 조건부서식 로직 변경 없음 — 순수 이동 리팩터링).

### PDF (`export_pdf.py`)
- `_build_table_element`가 `frame_width / ncols` 균등분할 대신 `get_style(document_type).column_widths`를 비율로 정규화해 `colWidths`로 사용. 스펙 열 개수보다 표 열이 많으면 초과분은 `DEFAULT_COLUMN_WIDTH` 비율로 채움(XLSX의 폴백 로직과 동일 원칙).
- `TableStyle`에 헤더 행 `("BACKGROUND", (0,0),(-1,0), HexColor)`, 헤더 글자색 `("TEXTCOLOR", ...)` 추가.
- 위험등급 컬럼(`risk_grade_headers`에 해당하는 헤더) 데이터 행마다 셀 값(A/B/C)에 따라 `("BACKGROUND", (col,row),(col,row), HexColor)`를 동적으로 추가.
- `CENTER_ALIGN_HEADERS`에 해당하는 컬럼은 `_CELL_STYLE`을 `TA_CENTER` variant로 교체.
- AI 제안값 셀은 `parse_ai_score_cell()`로 순수값만 넣고, 표 하나당 그런 셀이 1개 이상 있었으면 표 아래에 각주 문단(`"※ 굵게 표시되지 않은 수치는 AI 제안값, 현장 확인 필수"` 형태, 기존 XLSX 코멘트 문구 재사용) 1줄 추가.

### HWPX (`export_hwpx.py`)
- `doc.add_table(rows, cols, width=usable_width)` 직후 `hwpx_table.set_column_widths(style.column_widths)` 호출(열 개수가 스펙과 다르면 부족분은 `DEFAULT_COLUMN_WIDTH`로 패딩).
- 헤더 행과 위험등급 셀에 `hwpx_table.set_cell_shading(row, col, hex)` 적용.
- 헤더 매칭 컬럼은 `add_paragraph(align="CENTER")` 계열로 정렬 지정(정확한 셀 단위 API는 구현 중 `hwpx.oxml` 소스로 확인 — 설계 검토 중 `set_cell_shading`/`set_column_widths`는 존재를 확인했으나 "셀 단위 정렬" 설정 API의 정확한 호출부는 구현 시 재확인 필요).
- AI 제안값도 PDF와 동일하게 셀은 순수값만, 표 아래 문단으로 각주 1줄 추가.

## 데이터 흐름 / 에지 케이스

- **스펙에 없는 문서유형** ("기타 (직접 입력)" 등 자유 입력 문서유형): `get_style()`이 열너비 없는 기본 스펙(모든 컬럼 `DEFAULT_COLUMN_WIDTH`로 균등)을 반환 — 지금 XLSX의 기존 폴백 동작과 동일.
- **표 열 개수가 스펙보다 많음**: 초과 열은 `DEFAULT_COLUMN_WIDTH` 비율로 채움(XLSX에 이미 있는 로직, PDF/HWPX도 동일 원칙 적용).
- **위험등급 헤더가 없는 문서** (표준 작업계획서 등): `risk_grade_headers` 매칭이 안 되므로 조건부 배경색 로직 자체가 스킵됨 — 지금 XLSX 동작과 동일.
- **AI 제안값 각주는 표 단위로 붙인다** (문서 전체 1회가 아니라) — 여러 표가 있는 문서(예: 위험성평가표는 기본정보 표 + 본문 표 2개)에서 AI 제안값이 있는 표에만 각주가 붙는다.

## 테스트 계획

1. **XLSX 회귀**: 기존 `test_export_xlsx.py`, `test_export_xlsx_endpoint.py`가 리팩터링 후에도 그대로 통과해야 한다(값·타입·조건부서식 범위 불변 확인).
2. **PDF/HWPX 신규 검증 스크립트**: 오늘 QA로 만든 위험성평가표 레코드(재생성 또는 저장된 draft 재사용, 신규 API 호출 불필요)를 3개 포맷으로 내려받아, 열너비 비율·헤더 배경색·A/B/C 셀 배경색이 기대값과 일치하는지 자동 검증 (PDF는 `pypdf`로 텍스트만 추출 가능하므로 시각적 배경색 검증은 어려움 — reportlab에 넘긴 `TableStyle` 커맨드 리스트 자체를 검사하는 방식으로 대체).
3. **육안 확인**: 세 파일을 실제로 열어(또는 스크린샷) 나란히 비교 — 이번 세션에 QA로 생성해둔 위험성평가표 레코드 재사용.
