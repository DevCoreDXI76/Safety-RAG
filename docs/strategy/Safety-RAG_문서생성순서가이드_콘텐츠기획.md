# Safety-RAG 문서 생성 순서 가이드 — 콘텐츠 기획 초안 (2026-07-20)

전제: [Safety-RAG_역할별_액션플랜_체크리스트.md] 1절(기획자) #15 항목 실행 결과. 인앱 가이드 백로그(개발자 8번 항목, 웹 전환 이후 구현)와 연결되는 콘텐츠 기획입니다.

## 왜 필요한가

현재 4종 문서(위험성평가표, 표준작업계획서, TBM일지, 안전보건교육일지)는 서로 독립적으로 생성되지만, 실제 현장에서는 **위험성평가표의 내용이 표준작업계획서와 TBM일지에 그대로 이어져야** 합니다. 순서를 안내하지 않으면 사용자가 각 문서를 따로따로 만들면서 내용이 어긋나는 문제가 생길 수 있습니다.

## 제안하는 생성 순서

1. **위험성평가표** — 프로젝트 착수 시 최초 1회. 작업단계별 유해위험요인·안전조치·위험도를 정의하는 기준 문서.
2. **표준작업계획서** — 위험성평가표에서 정의된 위험요인을 특정 작업(예: 고소작업, 굴착)에 맞춰 구체화.
3. **TBM일지** — 위험성평가표 내용을 매일 아침 현장 조회용으로 요약 재구성. 작업 시작 전 매일 생성.
4. **안전보건교육일지** — 법정 교육시간·내용을 프로젝트 착수 시 또는 정기 주기로 별도 생성 (위 세 문서와는 독립적 흐름).

## 프로젝트 변경 시 재생성 시점

- 공사 종류가 바뀌거나(예: 배관 매설 → 고소작업 추가) 신규 위험요인이 발생하면 **위험성평가표를 먼저 갱신**하고, 표준작업계획서·TBM일지는 그 갱신 내용을 반영해 재생성하도록 안내해야 합니다.
- 단순히 매일 반복되는 작업이면 TBM일지만 갱신하고 위험성평가표는 유지.

## 인앱 가이드 UX 제안 (초안)

- 첫 문서 생성 시: "안전서류는 이 순서로 만드는 게 효율적입니다" 배너 노출 (위험성평가표 → 작업계획서 → TBM일지)
- 위험성평가표 생성 완료 후: "이 내용으로 표준작업계획서도 바로 만들어볼까요?" CTA 노출 — 이전 문서의 컨텍스트(작업단계·위험요인)를 다음 문서 생성 프롬프트에 자동 전달
- 프로젝트 변경 감지(사용자가 "공사 종류 변경" 등을 입력) 시: "위험성평가표를 먼저 갱신하세요" 안내

## 확인이 필요한 점 (베타 인터뷰 반영)

이 순서 가이드가 실제 현장 워크플로우와 맞는지는 가정입니다. 베타 0/베타 1 인터뷰에서 "실제로 어떤 순서로 서류를 작성하시는지, 이 순서와 다르다면 어떻게 다른지"를 확인해 이 기획을 검증·수정해야 합니다.
