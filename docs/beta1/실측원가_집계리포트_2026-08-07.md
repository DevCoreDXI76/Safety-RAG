# 문서유형별 실측 API 원가 재집계 (2026-08-07)

**작성 배경**: 베타1(18~20명) 준비 및 2026-08-07 BM 가격 재검토 초안(크레딧 기본안 + 구독 대안)의 마진 검증을 위해, `docs/strategy/Safety-RAG_문서유형별_실측API원가_2026-07-28.md`가 "베타1 확산 이후 재집계 권장"이라 명시해둔 재집계를 수행했다. 이 문서가 그 문서를 대체한다. 베타1이 아직 실트래픽을 만들기 전이라, 이번에도 `data/token_usage_log.jsonl`(로컬 개발·A/B테스트 로그, git 미추적)이 유일하게 존재하는 실측 데이터다.

## 로깅 현황

토큰 사용량 로깅은 정상 작동 중이다. `common.py`의 `log_token_usage()`가 문서 생성마다 `document_type`, `input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`를 `TOKEN_USAGE_LOG_PATH`에 append한다. 저장 경로는 `DATA_DIR`(`RAILWAY_VOLUME_MOUNT_PATH` 환경변수 — 로컬은 `./data`, 프로덕션은 Railway Volume) 하위 `token_usage_log.jsonl`. 필드 누락이나 문서유형 미구분 문제는 없어, 최소 로깅 구현 제안은 불필요하다.

**참고(별도 확인 필요)**: `api/cost_alert.py`의 `_entry_cost_usd()`는 `document_type`을 보지 않고 모든 로그 항목에 Sonnet 5 단가를 무조건 적용한다. 안전보건교육일지는 실제로 Haiku 4.5를 쓰는데도 이 함수와 이를 재사용하는 `/stats` 명령의 실시간 비용 표시는 Sonnet 단가로 계산해 원가를 과대 계상하고 있다. 이번 리포트는 이 함수를 재사용하지 않고 문서유형별 실제 배포 모델로 직접 계산했다. 코드 수정은 이번 작업 범위 밖이며 별도 확인·수정이 필요하다.

## 전제

- 배포된 모델 라우팅(`generate_draft.py`의 `MODEL_BY_DOCUMENT_TYPE`): **안전보건교육일지만 Haiku 4.5**, 나머지(위험성평가표·표준 작업계획서·TBM 일지)는 **Sonnet 5**. TBM일지도 Haiku 다운그레이드가 검토됐으나 "재해사례 창작"(15건 중 3건, 사망사고 포함) 문제로 Sonnet 유지가 최종 결정된 상태.
- 캐시는 `ttl="1h"` 기준으로 생성분은 입력가 ×2, 읽기분은 입력가 ×0.1.
- 환율은 1 USD = 1,400원 가정(추정치이며 실제 환율과 다를 수 있음).
- Sonnet 5는 두 단가 병기: **인트로가**(현재 적용 중, ~2026-08-31까지, $2/$10 per MTok)와 **표준가**(9월 이후, $3/$15 per MTok). Haiku 4.5는 단가 변동 계획이 없어 단일 값($1/$5 per MTok).

## 마진 검증 (크레딧 A안 기준)

크레딧 10건 8,900원 = **890원/건**(문서유형과 무관하게 1건=1크레딧 가정).

**최고 원가 문서유형은 표준 작업계획서**(인트로가 70원/건, 표준가 105원/건)다.

- 인트로가 기준 마진율: **약 92.1%** (890원 − 70원 = 820원)
- 9월 표준가 전환 후 마진율: **약 88.2%** (890원 − 105원 = 785원)

가장 저렴한 안전보건교육일지(약 19원/건)는 두 단가 모두에서 마진율 97% 이상으로, 4개 문서유형 전부 크레딧 단가 대비 원가 비중이 매우 낮다. 9월 단가 인상(Sonnet $2→$3, $10→$15)이 반영돼도 최고 원가 문서유형 기준 마진율이 92.1%에서 88.2%로 약 3.9%p 하락하는 수준이라, 이번에 확정된 크레딧/구독 가격 구조에 원가발 리스크는 크지 않다.

## 방법론 및 재현 방법

`data/token_usage_log.jsonl`(총 132줄)을 문서유형별로 집계하되, 아래 두 종류는 실측치 왜곡을 막기 위해 제외했다:

1. **더미/미대상 항목** — `테스트문서종류`(1건, 명백한 테스트 데이터), `협의체 회의록`(1건뿐, 요청 대상 4개 문서유형 밖) → 총 2건 제외.
2. **A/B 테스트 오염 태그** — 2026-07-16 Haiku A/B 테스트 때 TBM 일지·안전보건교육일지에 같은 입력을 Sonnet·Haiku 양쪽에 다 돌려본 기록이 `user_id`에 `ab_test_sonnet`/`ab_test_haiku`로 태깅되어 남아있다. 실제 배포 모델과 다른 쪽 태그는 제외했다 — TBM 일지는 `ab_test_haiku`(19건 제외, TBM은 실제로 Sonnet만 사용), 안전보건교육일지는 `ab_test_sonnet`(16건 제외, 안전보건교육일지는 실제로 Haiku만 사용). `user_id`가 `null`/`cli_local`인 항목(태그 없음)은 그 시점 배포 라우팅을 따랐다고 간주해 그대로 포함했다 — 이는 로그에 모델명 자체가 기록되지 않아 검증 불가능한 가정이다.

```python
# 필터링 핵심 로직 (전체 스크립트는 세션 스크래치패드에 있음)
MODEL_BY_TYPE = {
    "위험성평가표": "sonnet", "표준 작업계획서": "sonnet",
    "TBM 일지": "sonnet", "안전보건교육일지": "haiku",
}
# user_id == "ab_test_sonnet" 인데 이 문서유형의 실제 모델이 haiku면 제외
# user_id == "ab_test_haiku" 인데 이 문서유형의 실제 모델이 sonnet이면 제외
```
